# 可视化教学实现与核验

仅在制作、修改或验证交互演示／动画，或需要核对教学模型时读取；已有说明直接复用。触发判断与六步教学流程以主 Skill 为准。本文件不要求每个知识点建立网页。

## 先确定教学问题

明确当前课程定位、要解决的理解障碍、一个主要观察量、一个关键操作，以及演示后要能解释的公式或解题结论。沿用课件符号、正方向、单位、条件和掌握深度；简化或补充与原图不同之处须说明。

根据收益选择形式。例如：磁场／电流方向可先画带方向的静态图；阻尼比与响应关系适合参数曲线；电机转动或信号传播适合时间演示；CPU 指令周期适合可暂停、逐步推进的状态演示。例子仅用于选型，不自动扩大学习范围。

如果静态图已足够，就停在静态图。开发量较大的演示先说明能帮助观察什么，再结合当前卡点与学习时间决定必要范围，优先缩小到当前关键关系。

## 轻量实现

- 优先使用现有项目环境和已有教学页面／组件，采用 HTML、CSS、JavaScript；避免无必要的依赖、框架和复杂部署。简单模型宜使用可直接打开的本地 HTML。
- 滑块、输入框、开关、按钮等必须真实可操作。参数变化后，基于同一状态重新计算，相关图形、数值、单位和逻辑状态同步刷新；动画时间与显示状态保持一致。
- 曲线来自当前输入下的公式、算法或明确说明的数值求解。可用预计算数据作已标注的静态对比，但不能把预画曲线或替换图片冒充实时计算。
- 随时间变化的演示按教学需要提供播放／暂停、复位；步骤型过程提供单步推进，使用户能停在关键状态观察因果。
- 输入范围须符合模型适用条件；对无效输入或不支持的情形明确反馈。显示必要的坐标、图例、变量、单位、方向、初始条件和模型假设，不把简化教学模型表述为真实系统完整行为。
- 页面只保留帮助理解的控件与说明；保持图形、公式和数值易于对照，不用装饰或实现细节分散注意力。

## 数学与交互核验

先核对公式、符号、单位、初始条件和模型适用范围，再核对代码。选择有物理或数学意义的代表值、边界值及可解析／手算的已知情形检查输出。检查趋势、极限行为、状态转移和数值精度是否支持当前教学结论；参数跨越公式分支或模型范围时按适用情况计算或明确限制，不能继续套用失效表达式。

使用可用浏览器或预览工具实际操作关键控件，检查一次关键参数变化后曲线、数值与状态是否一起更新，并检查暂停／单步／复位等实际提供的功能。核验以教学结论和交互行为为准，不为了页面数量增加重复测试。若无法运行或操作，明确说明验证范围，不能声称已验证交互。

## 交付与接回课程

环境支持时直接打开或提供页面预览；否则给本地文件的绝对路径链接及最短启动方法。若确需本地服务，说明启动命令与访问地址。不要只展示页面截图代替用户操作入口。

演示时指出一个具体观察重点，邀请用户只改变一个关键参数或推进一步，再把观察结果接回对应公式／原理与一道简单理解题。不能自问自答后把用户记为已理解；用户选择跳过时保留未验证状态，并回到原定课程任务。

同聊天优先复用页面与当前参数。只有到原有真实保存节点且会影响恢复时，才在 learning-state 中简记演示路径、模型假设、关键参数或未解决问题与下一动作，不新增逐轮保存要求。动态参数与课程进度不写入 Skill 或全局记忆。
