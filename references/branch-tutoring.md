# 可选分支答疑

仅用户明确要求“另开答疑聊天／单独讨论这个问题／开分支”等时加载。普通理解性追问在当前聊天回答；旧默认分支约定不触发创建，也不先询问要不要分支。

## 明确请求后的最小流程

1. 保存本次疑问、主线暂停位置、原定下一点和必要材料定位；跨聊天交接是一次持久化节点。
2. 使用当前可用的聊天创建／分叉工具，遵循工具实际要求。已知工具不重复发现；不创建 worktree、不改模型，也不用后台代理替代用户可进入的聊天。
3. 初始 prompt 一次带齐：答疑角色、用户疑问原话、刚讲的背景与符号、可访问的材料／页码／必要图、答疑范围、主线恢复点。未知聊天 ID 不编造，必要时用状态路径关联。只复核确实不确定的材料访问，不假定新聊天拥有原附件。
4. 展示工具确认的入口／创建标识并保存实际 ID。仅按工具约定做必要的派发确认；不轮询“是否学懂”。同一疑问连续追问复用同一聊天。
5. 创建失败时保留断点与精简交接，说明失败，不反复创建重复聊天。工具不可用则提供交接供用户另开。准备中的 clientThreadId 不当作 threadId 使用。

主线等待用户返回，不在答疑期间自主推进。无需强制单独回执文件或复制全篇历史。

## 支线与返回

交接明确要求支线只解决当前疑问，不再创建支线或修改主线进度。沿用来源和符号，没懂就降低解释层级；提供简短结论、必要更正、未解决项和返回位置。没有用户反馈就不标为理解／掌握。

用户回到主线后，若所需结论已在当前上下文，直接复用；确实缺少影响教学的信息时，读取必要的最近支线内容或已有摘要一次，不做状态轮询或完整重放。以一句衔接恢复断点；关键问题仍未解决时先补足。

工具报告“一轮回答完成”不触发主线续讲，也不是理解证据。跨聊天发送消息须有工具要求的用户授权；默认由主线在用户返回时按需读取，不安排主动回报。流程一经在本次上下文明确，相关续问不反复加载本参考。
